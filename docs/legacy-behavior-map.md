# Legacy behavior map

The reference archives were inspected read-only, by listing members and selectively reading authored source in memory. They were not unpacked into this repository. The implementation preserves useful behavior and domain relationships; it does not port the legacy code, dependencies, configuration, or data.

## Article context

Julia's [The Chart That Had to Grow Downward](https://dev.to/julia_rakitina/the-chart-that-had-to-grow-downward-20h3) explains why well logs use downward depth, independent horizontal scales, depth-only zoom, and explicit SVG clipping. It also identifies preserving an operator's inspected viewport during live acquisition as a separate requirement from simply redrawing a chart. Those principles guide the modern chart architecture.

The public article was read through the DEV API after the ordinary page endpoint rejected automated access. No article images or source passages were copied into the product.

## Evidence boundaries

- **Observed in source:** the behaviors mapped above, calibration and recording code, sensor-stream structure, and visualization scaffolding.
- **Provided by Julia:** she designed and implemented the foundational system in 2015–2016; the core sensor chain and software were field tested; high encoder pulse rates exposed an Arduino acquisition bottleneck; a later descendant changed acquisition hardware and software and was commercialized in 2026.
- **Not established by archive inspection:** later implementation authorship, certification, current production reliability, customer/deployment identities, or complete field integration of an inclinometer.
- **New portfolio decisions:** deterministic synthetic scenarios, explicit lifecycle and acquisition-quality models, bounded storage, replay semantics, modern accessibility, and tests. These are modern engineering choices, not historical claims.
